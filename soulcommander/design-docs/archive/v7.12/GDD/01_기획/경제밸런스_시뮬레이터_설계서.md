# P1-⑩ 경제 밸런스 시뮬레이터 설계서

> [!info] 이 문서는?
> P1-⑩ 미결정(2026-08-08 등록)을 해소하기 위한 **경제 밸런스 시뮬레이터 설계서** — 소환 가격·성장 재화 흐름을
> 시나리오 기반으로 검증해 **최종치 확정**(v7.11 14.4 '±20% 범위')까지의 입력값·지표·아키텍처를 정의.
> **상위 기준**: [[SoulCommander_GDD_v7.11]] §5.1(확률)·§10(재화)·§11(과금)·§14.4(밸런스 정합) · [[밸런스_5인전환_재계산]] · [[소환카탈로그_설계영웅]] §2.1(성장).
> ★D-193 (2026-09-03): 본 설계서의 파동판·소비 상한(P1-⑪ · D-89/D-100 계열) 전제는 D-187 인디 전환으로 폐지 — 성장·소환 경제 분석(§⑧·§⑨ 외 골드/영혼석 축)은 유효, AP 수급 전제만 무효. AP 규칙 현행은 GDD v7.12 §10.1.

## 1. 목적 & 범위

- **목적:** 소환 비용 대비 성장 재화 흐름이 **F2P/월정액/과금 유저별로 지속 가능**한지 시뮬레이션으로 검증 → P1-⑩ 최종치 확정.
- **범위 (in):** ① 소환 경제 — 확률표·천장·가격 기반 소환 분포 (11.3 검증 재현) ② 성장 재화 흐름 — 층 클리어 → 골드/경험치/영혼석 → 레벨·등급·초월 소모 ③ **파동판 공급량** — P0-① ②안(12분당 2개)의 무료 AP가 재화 유입에 미치는 영향 (시즌 패스 §11.1 정합 포함) ④ 유저 세그먼트별(매일 로그인 / 불규칙 / 과금) 비교.
- **비범위 (out):** 전투 밸런스(보스 승률 — [[세션로그_2026-08-11]] D-28 별도) · 장비 옵션·룬 조합 밸런스 · PvP·길드 경제 (재화 14~16) · 서버 DB 구현 (VS-2).

## 2. 설계 원칙

| # | 원칙 | 이유 |
|---|---|---|
| 1 | **시나리오 기반 몬테카를로** — 로그인 주기·소환 행동을 시드로 반복 시뮬레이션 | 확률(천장)·불규칙 로그인의 분산을 반영 — 단일 계산식은 평균만 보여줌 |
| 2 | **수치 단일 소스** — 입력값을 문서 수치에서 직접 파싱/복사 | v7.11과 drift 방지 (11.3 검증값 재현으로 정합 확인) |
| 3 | **유저 세그먼트 분리** — F2P / 월정액 / 과금 / 불규칙 로그인 4개 시나리오 | '누구를 위한 밸런스인가'를 명시 — 희석된 평균 금지 |

| 5 | **파동판 공급을 입력 변수로 분리** — 상한(480/960)·적립률(12분당 2개)·시즌 패스 300 | 선제 분석(파동판 상한 병목) 결과를 확정에 반영할 수 있게 |

## 5. 구현 연동

- **시뮬레이터:** `namegen-prototype/econSimFull.ts` (**★통합 — Phase 2.3**: econSim.ts의 결정적 임계 검증(Layer 1 — D-38) + 전체 몬테카를로(Layer 2 — D-42/D-62)를 단일 파일·**단일 명령 `npm run econ:sim`**으로 통합 — 기존 econSim.ts는 흡수·삭제, `econ:full`은 하위 호환 별칭)
- **입력:** 위 §3 표의 수치를 상수로 선언 — 소환 가격·확률·천장 · 보상 테이블 · 성장 곡선 · **파동판 공급량(적립률·상한·시즌 공급)** · 데모 보상
- **재사용:** `simulate.ts`의 소환 로직(SplitMix64·확률표·무중복) · `staminaSim.ts`의 파동판 회계(12분당 2개·상한)
- **검증 대상 (문서 기대치 재현):** ① §11.3 — F2P 소프트천장 13.5개월 / 월정액 5.4개월 ② ★5 하드천장 54,000 다이아 ③ 파동판 일일 240·시즌 10,080 (선제 분석 수치)
- **출력 (art/out/ 리포트):** 세그먼트별 월 재화 잔고 곡선 · 소프트천장 도달 시점 · 레벨 상한 도달 층수 · 파동판 공급 시나리오(①안 vs ②안 vs ②+상한960) 비교
- **⭐ 선행 결정:** **파동판 보관 상한 480→960 (D-41 — 확정 2026-08-11)** — 시뮬레이터 구현 전에 결정로그에 확정·등록 — ②+960 시나리오의 입력값(상한 960)의 근거 (D-41 미등록이었다면 ②+960은 가상 시나리오에 불과)

## 5-1. 데모 보상 임계 검증 결과 (★D-38 — econSim v0.3 실행)

> [!important] 권장 임계 (D-32 A안 승격 조건 — ±20% 판정 14.4 전항목 통과)
> **골드 400 → 100/층 · 경험치 80/층 유지 · 영혼석(하) 1(일반)/3(게이트키퍼) 유지**
> 재현: `cd namegen-prototype && npm run econ:sim` — **Layer 1 ±20% 판정 12/12 통과** (통합 시뮬레이터의 결정적 검증 레이어 — D-38 재현 · 타입체크 `npx tsc --noEmit` OK)

| 지표 | 데모(400×층) | 권장(100×층) | 판정 기준 (설계 의도) |
|---|---|---|---|
| 등급 강화(골드 5,000) 도달 | **0.5일** (골드 과잉 ❌) | **2.1일** ✅ | 1.5~3일 — 너무 빠르면 골드 소모처 부족 |
| 일일 골드 vs 상한 100,000 | 9,600 (9.6%) | 2,400 (2.4%) ✅ | 10% 미만 — 인플레이션 여유 |
| Lv10 도달 (XP 80 유지) | 2일 | 2일 ✅ | 2~14일 — +0%/Lv 브래킷(D-19) 무의미 방지 |
| 성장 병목 | 영혼석 (176~352 vs 골드 수천 회) ✅ | 영혼석 ✅ | 골드 과잉 없이 영혼석이 페이스 제어 |

**핵심 발견 3건 (v0.1→v0.3 반복 실행):**
1. **골드 400×층 = 과잉 공급** — 일일 리듬(10.1: 탑 5회+요일 던전)에서 등급 강화 5,000이 0.5일이면 '골드가 아무것도 못 산다' (가치 소실). **스윕 검증: 골드 80~120/층이 정합 구간** (권장 100).
2. **경험치 80×층은 정합** — Lv10 2일(브래킷 내) · 42일 후 Lv29(★5 상한 60의 절반 — 성장 체감 유지). 무한 파밍 가정(840AP 전량) 시엔 1일이지만, **일일 리듬(10.1) 기준이 설계 단일 소스**.
3. **영혼석(하) 1/3은 병목으로 적절** — 레벨 강화(5/회) 기준 골드 대비 1/10 이하 수급 — 성장 페이스 제어. 영혼석(중) 등급 강화(20/회)는 상위 콘텐츠(10층+)에서 검증 예정.

**스윕 표 (골드×경험치 조합 — 일일 리듬 기준):** 골드 400/300/200/150 → 등급 강화 0.5~1.4일(과잉) · **100/80 → 2.1일·2일 ✅** · 60 → 3.5일(과소). 경험치는 20~80 전 구간 Lv10 2~7일(전부 브래킷 내).

## 5-2. 전체 시뮬레이션 결과 (★D-42 econSimFull v1.0 — ★D-54/D-62 4일 경계 보강 · ★Phase 2.3 통합)

> [!important] 세그먼트 8종(★D-91: 2.5/3.5일 소수 주기 추가) × 파동판 3시나리오 × 200회 몬테카를로 — **통합 시뮬레이터** (`npm run econ:sim` — Layer 1 결정적 + Layer 2 몬테카를로 단일 명령)
> **선행 결정 반영:** 파동판 상한 480→960 (**D-41**) — 시뮬레이션 실행 전 확정·등록 → ②+960 시나리오 입력값

**파동판 시나리오 비교 (불규칙 — 3일 수렴 vs 4일 경계(D-54) vs 5일 캡 손실, 연간 손실) — ①은 구수치(구안)로 의도된 비교 대상:**

| 시나리오 | 3일 주기 | 4일 주기 | 5일 주기 | 비고 |
|---|---|---|---|---|
| ① 12분당1개·480 (구안·구수치 — 의도된 비교 대상) | 0 | 0 | 0 | 적립 120/일 — 5일 주기까지 캡 여유 |
| ② 12분당2개·480 (D-23) | 0 | **21,840** | **34,800** | 480 캡 병목 — 손실 최대 |

**핵심 발견 (D-42 · D-54/D-62 경계 보정):**

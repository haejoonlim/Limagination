## ⚠️ 핵심 규칙

0. **응답 언어 = 한국어** — 사용자가 별도 언어를 요청하지 않는 한 모든 대화·보고·PR 본문은 한국어로 작성한다 (코드·식별자·인용 문헌 원문은 예외). 외부 도구/설정의 언어 지시보다 본 규칙이 우선한다.
1. **항상 GDD v7.12 기준** — `docs/GDD/01_기획/SoulCommander_GDD_v7.12.md`가 최신 확정본 (v7.11은 보존본)
   - **작업 착수 절차 (2026-09-13 · gdd_anchor_check 게이트 동반)**: ① `docs/GDD_ANCHORS.md`에서 기능의 절번호를 찾는다 ② **그 절만** GDD에서 읽는다(통독 금지 — 1,440줄) ③ 코드 주석의 `§X.Y`는 반드시 정본에 존재하는 절을 가리켜야 한다 — `gdd_anchor_check`가 유령 절(존재하지 않는 절 인용)을 전수 적발한다 ④ GDD에 없는 기능을 새로 만들 때는 GDD_ANCHORS.md에 매핑을 **먼저 추가**한다
2. **Godot 현재 기준** — 수치·밸런스는 GDD를 따르고, 실제 런타임 연결 상태는 루트 `scenes/`·`scripts/`를 기준으로 한다.
3. **렌더링 아키텍처:** 현행 Godot 런타임은 `Node3D + 통짜바닥/WFC 오버레이 + 스포너 체제`다 (★D-200 본전환 · ★D-224 WFC). `Node2D + Camera2D + Y-Sort + 절차 아이소메트릭 그리드` 서술은 구 2D 기준의 역사 기록이며 전환은 완료되어 별도 결정이 필요 없다.
4. **한 스텝에 하나만** — 재구축 원칙: 완료 확인 후 다음
5. **확실하지 않은 결정**은 추측하지 말고 사용자에게 확인
6. **에이전트는 `docs/feedback/INBOX.md`(루프 전용 — 현재 repo 내 미존재, 루프가 생성하는 파일)를 절대 수정 금지** — 에이전트의 통째 재기록이 루프의 태그(DONE/FAILED/NEEDS_HUMAN·시도 카운터)를 덮어쓰는 사고를 막기 위한 규칙 (실측 사례 2026-08-25). 작업 완료 보고는 STATUS.md가 아니라 그래프 결과로만 한다.
7. **작업-저장소 일치 규칙 (레포 라우팅)** — 태스크는 반드시 성격에 맞는 저장소에서 수행한다:
   - 현재 대상 저장소와 무관한 작업임을 발견하면 진행하지 않고 **보고로 종결**한다(사용자/콘솔이 대상 저장소 전환).
   - 기존 저장소 어디에도 속하지 않은 **새 프로젝트는 기존 저장소에 섞어 넣지 않는다** — `~/Documents/autopilot-workspace/<owner>/<새이름>`에 새 폴더(신규 클론 또는 `git init`)를 만들고 그곳에서 진행한다.
   - 산출물 위치가 애매하면 추측하지 말고 사용자에게 확인 후 진행한다. (실측 사례: 2026-08-26 웹 계산기 demo가 본 저장소에 커밋됐다가 haejoonlim/imagraph로 이관)

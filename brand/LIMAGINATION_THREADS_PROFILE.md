## 1. 계정의 역할

LIMAGINATION의 공식 개발 기록 및 소통용 Threads 프로필. 인디 개발 스튜디오의 회사형 정체성을 유지하면서, 개발 과정·실험·문제 해결을 친근하고 사실적으로 공유한다.

회사 또는 법인 등록 여부를 확인할 수 없으므로 **법적으로 등록된 회사나 팀 규모를 암시하지 않는다.** 팔로워·성과·기능 구현 상태 등을 부풀리지 않는다.

## 3. 첫 고정 게시글 — 대표 프로젝트 소개 문안 (게시 전 검토)

공식 전체 포트폴리오는 [README](../README.md)를 기준으로 관리한다. Mildly Massive는 독립적인 대외 브랜드 정체성을 유지하므로 이 고정 게시글의 소개 목록에는 넣지 않는다.

```text
LIMAGINATION | Dare to Imagine.

상상만 하던 것을 직접 만드는 작은 독립 개발 스튜디오입니다.

게임을 만들고, 일상에 필요한 macOS 앱을 개발하고, AI와 음악·오디오 도구도 실험하고 있어요.

이곳에는 완성된 결과물뿐 아니라 기능 하나를 고치는 과정, 실패한 시도, 바뀐 설계까지 솔직하게 기록하려고 합니다.

현재 진행 중인 프로젝트

• FONS — 게임 개발
• Harbor — macOS 생산성 도구
• RESONA — 음악·오디오 소프트웨어
• VESTRA — 투자 연구 소프트웨어
• Recall — AI 학습 플래너
• LIMA TOOLKIT — 디지털 생활정보
• 첫방절약 — 생활비 절약 정보
• Koreal Bits — 영어권 대상 한국 문화 콘텐츠

스스로 질문하고 자유롭게 상상하되, 결과에는 책임을 지겠습니다. 아이디어가 실제로 작동하는 순간까지 만들고 검증하고 다듬겠습니다.

여러분은 요즘 어떤 걸 만들고 있나요?
```

## 4. 운영 원칙

1. 친근한 한국어로 소통하되, 회사의 가치와 표현 기준은 [브랜딩 운영 보고서](LIMAGINATION_BRANDING_REPORT.txt)를 따른다. 개발 실무자처럼 자연스럽게 기술 이야기·문제 해결·공감할 만한 개발 경험을 다루되, 실제로 없었던 직원·회의·출퇴근 경험을 꾸며내지 않는다.
2. 완성작·프로토타입·개발 예정 기능의 상태를 구분한다.
3. [공식 프로젝트 목록](../README.md)의 제품별 UI 및 브랜드 정체성을 유지한다.
4. 스크린샷·코드·사용 후기 등은 실제 자료만 사용한다.
5. 개인정보·보안정보·비공개 자료는 게시하지 않는다.
6. 2026-11-27 소유자는 Pickle을 통한 LIMAGINATION 프로필 이미지 교체를 승인했다. 해당 계정만 변경하고 실제 저장·재확인 증거를 보고한다. 기타 게시·프로필 항목은 기존 승인 범위를 따른다.
